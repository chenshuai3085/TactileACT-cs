2026-04-20  G-TCL: 物理门控时序对比学习 (Gated Temporal Contrastive Learning)

  背景:
    Stage 1 Latent Foresight 只用 L1 + obs_aux loss, 静态帧和动态帧被无差别对待。
    Bounce 瞬间预测滞后 (L1 回归导致平滑), 模型不理解物理时机。

  核心设计:
    Δφ = ||z_{t+H} - z_t||₂ 门控对比学习:
    - 静态 (Δφ < ε): 只拉近正样本 (positive alignment only)
    - 动态 (Δφ > ε): 完整 InfoNCE: hard neg (z_{t+H-1}) + batch neg (B-1)

  Δφ 统计 (260407全量 180ep, 8219帧):
    Bounce (N=5131): mean=4.838, std=4.956, p50=2.982
    Success (N=3088): mean=3.359, std=4.031, p50=1.965
    Combined (N=8219): mean=4.282, p50=2.509
    → ε=2.5 (combined p50), 50.1% 帧为动态

  实现:
    - GatedTemporalContrastive 类 (foresight_transformer.py)
      - Projection Head: 144 → 144 → 64, L2 normalize
      - Learnable log_temp, clamp [0.01, 100] 防爆
      - Batch负样本用矩阵乘法 q @ k_pos.T → O(B²) 高效
    - 通过 use_gtcl 配置开关控制, 默认关闭, 完全向后兼容
    - Loss: L1_latent + 0.3*obs_aux + 0.1*G-TCL

  文件改动:
    - TFAC_V5/foresight_transformer.py: 末尾追加 GatedTemporalContrastive
    - TFAC_V5/pretrain_latent_foresight.py: 兼容扩展 (z_current/z_gt_prev 返回, compute_loss 扩展)
    - TFAC_V5/config_pretrain_gtcl.json: G-TCL 实验独立配置
    - TFAC_V5/eval_latent_foresight*.py: 适配 5 个返回值

  运行方式:
    python TFAC_V5/pretrain_latent_foresight.py --config TFAC_V5/config_pretrain_gtcl.json

2026-04-16  TFAC V4 (LDG) 完整实现
---------------------------------------------------------------
任务: 基于 V3 问题分析和论文调研，设计并实现 TFAC V4 (TFAC-LDG)
目标: CoRL 2026 论文, 故事线 Think → Dream → Verify → Act

【V3 五大问题】
1. 单 token 触觉瓶颈: 81个标志点压缩到1个token，空间结构丢失
2. 只用最后帧: 10帧预测只取 frame[9]，中间帧信息浪费
3. A1 完全 detach: foresight 质量无法反传到 draft action
4. 弱对比学习: 63个负样本, GT contrastive 禁用, lambda=0.1
5. SpatialTactileDecoder: 从单一全局向量重建 9×9 损失大

【V4 五大创新 (C1-C5)】
C1: SpatialMarkerEncoder — 9 spatial patch tokens
   - (B,9,9,2) → per-point MLP(4→64→128→D) → +pos_embed → 2-layer SelfAttn → 3×3 patch_pool → (9,B,D)
   - 保留空间结构，支持per-patch对比学习

C2: Latent Prediction + Dynamic-Aware Weighted Loss
   - 在潜在空间监督: encode GT marker → spatial tokens → smooth_l1 vs predicted tokens
   - 动态权重: weight = sqrt(change/mean_change)，变化大的帧权重更大

C3: Tactile Consistency Loss (核心创新)
   - 动作→触觉因果验证: TactileDynamicsModel 预测 z_next
   - Margin ranking: sim(z_pred, z_gt_next) > sim(z_pred, z_random) by margin=0.2
   - 验证 foresight 预测的触觉轨迹与实际动力学一致

C4: Temporal Differential Residual Action
   - A2 = A1 + sigmoid(alpha) * deltaA
   - alpha 可学习，初始化 0.1 (sigmoid ≈ 0.525)
   - TactileTrajectoryEncoder: 时序差分编码 [frame0, diff1, diff2, ...] → summary

C5: Multi-level Contrastive Learning
   - Spatial: per-patch InfoNCE, (B,9,D) vs (B,D) → B*9 负样本
   - Temporal: margin ranking, 相邻帧 > 远距帧
   - GT alignment: 预测视觉 vs GT视觉 标准 InfoNCE

【新增模块】
- TFAC_V4/marker_encoder.py: SpatialMarkerEncoder
- TFAC_V4/foresight_transformer.py: ForesightTransformerV4, PatchLevelDecoder, ForesightContrastiveV4

2026-04-16  TFAC V4 训练调优 (OOM 修复 + AMP)
---------------------------------------------------------------
任务: V4 首次正式训练 (0414 数据集, 162 episodes, 2000 epochs)

【OOM 问题与修复历程】
1. batch_size=64: epoch 0 validation OOM (23.9GB/24.6GB)
2. batch_size=32: epoch 4 training OOM (sampling loss rollout 累积显存)
3. batch_size=16 + grad_accum=2: epoch 14 OOM (19.5GB allocated + 2GB fragmentation)
4. batch_size=8 + grad_accum=4: epoch 18 OOM (19GB + 2.5GB fragmentation)
5. + sampling loss detach (中间步骤不保留梯度图): epoch 19 OOM (仍然太接近上限)
6. + AMP 混合精度: epoch 20 OOM (19GB peak 未显著下降)
7. batch_size=4 + grad_accum=8 + AMP + CPU state_dict: epoch 1 matplotlib tkinter crash
8. + matplotlib.use('Agg'): 当前运行中，预期稳定

【根因分析】
- V4 模型 122M 参数, 包含: 共享encoder + 双decoder(7+7层) + foresight(3层) + dynamics + trajectory encoder
- Sampling loss 做 3 步自回归展开, 每步一个 foresight forward pass
- 训练 ~20 epochs 后 CUDA 内存碎片化导致 OOM (reserved but unallocated ~2.5GB)
- Peak memory 稳定在 ~19GB, 24GB GPU 仅余 ~5GB, 碎片化后不足

【最终训练配置】
- batch_size=4, grad_accum_steps=8 (有效 batch=32)
- AMP 混合精度 (GradScaler + autocast)
- Sampling loss 中间步骤 detach (仅最后一步保留梯度)
- Best checkpoint 实时保存 (不等训练结束)
- State_dict 存 CPU (节省 ~490MB GPU)
- torch.cuda.empty_cache() 每 epoch
- matplotlib Agg 后端 (避免 tkinter crash)
- ~107s/epoch, 预计总训练时间 ~60 小时

【早期收敛趋势 (前 15 epochs, 非 AMP+bs4 run)】

2026-04-16  V4 Ablation 实验 (V1 recipe + SpatialMarkerEncoder)
---------------------------------------------------------------
任务: V4 CLIP backbone 训练效果差 (plateau 0.171)，需要深度分析根因并迭代

【V4 vs V1 根因分析】
问题: V4 best l1_final=0.171 (CLIP) / 0.155 (ImageNet) vs V1=0.072

核心差异 (V4 → V1):
1. kl_weight: 1 → 10   → V4 KL=0.00004 完全崩塌, V1 KL 正常
2. a2_init: "residual" → "a1_refine"  → V4 A2≈A1 (cosine=0.998), V1 A2改进6.5%
3. 12 个 loss 竞争 → 6 个简洁 loss   → V4 loss 之间互相干扰
4. batch_size: 有效32 → 64           → V4 被 OOM 限制
5. predict_horizon: 10 → 1            → V4 多帧预测远帧退化 3.3x
6. fusion: contact_gate → gate        → V4 过度复杂
7. dec_layers_draft: 7 → 3            → V4 draft decoder 过重
8. lambda_foresight_vis: 0.3 → 0      → V1 禁用视觉预测 loss

【隐藏 Bug 发现】
predict_horizon=1 + foresight_horizon=10 → 数据集返回 (B,10,9,9,2)
但模型期望 (B,9,9,2)，dim 不匹配导致 foresight loss 全部静默为 0！
修复: _compute_gt_future_features 中提取最后一帧

【V4 Ablation 策略 (回归 V1 + 保留 SpatialMarkerEncoder)】
- 假说: V4 的 SpatialMarkerEncoder (9 spatial tokens) 是有价值的创新
  其他创新 (C2-C5) 同时引入导致训练不稳定
- 方法: 用 V1 验证过的 recipe + 只加 SpatialMarkerEncoder
  如果 V4.1 > V1 → C1 是有效创新，可以逐步加回 C2-C5
  如果 V4.1 < V1 → C1 可能有害，需要重新设计

2026-04-16  V4 Ablation1 诊断 + 关键 Bug 修复
---------------------------------------------------------------
任务: 分析 ablation1 为什么远差于 V1 (0.206 vs 0.072)

【Ablation1 训练结果】
- Best: val l1_final=0.206 @ epoch 45
- Epoch 55: 0.280 (显著回升, 过拟合开始)
- 在 epoch 60 停止训练

【发现三个关键 Bug】

Bug 1: 课程学习完全失效
  V4 model.forward() 接收 use_predicted_future 参数但从未使用
  → 融合 gate 始终看到噪声预测, 从未看到 GT 触觉
  → V1 前 40% epochs 用 GT 触觉, 教会 gate "未来触觉有用"
  修复: 当 use_predicted_future=False 时, 将 GT 触觉编码通过
  SpatialMarkerEncoder 后送入 gate

Bug 2: 空间信息在融合前丢失
  SpatialMarkerEncoder 产生 9 个空间 tokens (9, B, D)
  但在送入 gate 之前 mean-pool 为 (B, D) 单向量
  → C1 的空间结构优势完全丧失
  → 和 V1 的 PointNet 直接输出 (B, D) 等效
  (此问题需要更深层架构改动, 留待 V5)

Bug 3: Ablation 配置与 V1 实际 recipe 多处不符
  参数              V1 实际    Ablation1    影响
  dec_layers_draft  7          3            draft decoder 过弱
  curriculum_ratio  0.4        0.75         课程切换时间点错误
  foresight_vis     0          0.3(硬编码)  V1 禁用视觉预测 loss
  foresight_horizon 8          10           预测范围不同

【修复内容】
1. TFAC_V4/tfac_model.py: 实现 curriculum 切换逻辑
   - use_predicted_future=False: GT → marker_encoder → spatial tokens → gate
   - use_predicted_future=True: 使用 foresight 预测的 tokens
2. TFAC_V4/tfac_policy.py: lambda_foresight_vis 从硬编码 0.3 改为可配置
3. TFAC_V4/train.py: 新增 lambda_foresight_vis 参数传递
4. config_v4_ablation2.json: 真正匹配 V1 recipe
   - dec_layers_draft=7, curriculum_ratio=0.4
   - lambda_foresight_vis=0, foresight_horizon=8

【Ablation2 训练结果 (epoch 30 停止)】
- Val l1_final: 1.55→0.24→~0.20 (收敛中但减速明显)
- gate_traj: 0.34→0.28 (持续下降, 即使在 GT curriculum 阶段)
- gate_a1: 0.335→0.37 (上升, 模型依赖 A1 而非触觉)
- KL: 40→0 (快速崩塌)
- 结论: curriculum 修复有效但 mean-pooling 瓶颈才是根因

2026-04-16  V4 Ablation3: Token Fusion (空间 tokens 直接 cross-attention)
---------------------------------------------------------------
任务: 用 token fusion 替代 gate fusion, 保留空间结构

【核心问题】

2026-04-16  V4 深度分析 + FiLM 融合实现
===============================================================
【V4 失败根因分析】

1. SpatialMarkerEncoder 空间 tokens 无法有效传递到 action:
   - Gate fusion: 9个空间tokens必须mean-pool→1个向量才能gate → 空间信息丢失
   - Token fusion: 9个tokens添加到210+个memory tokens → ~4%注意力容量, 被稀释
   - 结论: 空间 tokens 的优势被融合方式彻底消解

2. 对比学习温度爆炸 (V1和V4都有此问题):
   - log_temp 无约束, 从 0.07 涨到 16+ → InfoNCE loss 退化为常数
   - V1 成功不依赖对比学习 (V1也温度爆炸但仍达到0.072)
   - 修复: clamp log_temp to [-2, 2]

3. V4 过拟合更严重 (118M params vs V1 114M):
   - SpatialMarkerEncoder 额外参数 + SelfAttn 增加了过拟合风险
   - 小数据集(337 episodes)不足以支撑更大模型

【FiLM 融合设计 (Foresight-conditioned Adaptive Layer Modulation)】

核心思路: 不修改 memory, 在 decoder_final 每层后用 foresight 特征调制隐状态。
  output = output * (1 + γ_i(z_foresight)) + β_i(z_foresight)

设计优势:
  1. 细粒度条件化: 7层decoder每层独立的γ/β, 比gate的1次全局融合更精细
  2. 渐进学习: γ/β零初始化, 训练初期≈恒等映射, FiLM信号逐步增强
  3. 不增加memory维度: 不像token fusion添加额外token导致注意力稀释
  4. 兼容gate: gate_film模式同时保留gate融合 + FiLM调制

实现方式:
  - "film" mode: memory不变, 仅靠FiLM调制
  - "gate_film" mode: gate融合enriched memory + FiLM双重条件化
  - 新增 _run_decoder_with_film() 方法替代 _run_decoder()
  - 参数量: film=114.71M, gate_film=118.13M

【同步修复】
  - contrastive temperature clamp: log_temp.clamp(-2, 2)
  - latent foresight loss: smooth_l1(predicted_encoded, GT_encoded.detach()), λ=0.3
  - train.py: 添加 lambda_latent_foresight 参数传递

【验证】
  - film 和 gate_film 两种模式均通过 shape test (scripts/test_film.py)
  - 所有loss正常, 形状正确, inference输出正确

【Gate Fusion 核心问题分析】

Gate fusion 的数学本质:
  fused[i] = w_mem * mem[i] + w_fut * fut + w_a1 * a1
           = 0.33 * mem[i] + 0.33 * fut + 0.33 * a1
           = 0.33 * mem[i] + constant_bias

三大问题:
  1. Memory 信号衰减 67%: 空间信息被严重削弱
  2. Foresight 信息是 rank-1: 所有位置收到相同的 future 向量
  3. 无空间选择性: 所有 memory 位置统一加权

验证: V1 0401 foresight_tac=0.004 (预测质量极好) 但 A2 仅提升 10%
  Pearson 相关 r=-0.119: foresight 质量与 A2 提升几乎不相关
  → 瓶颈在 fusion 机制, 不在预测质量

FiLM 的优势:
  layer_out = layer_out * (1 + gamma(fut)) + beta(fut)
  1. Memory 全强度保留 (不被缩放)
  2. 7层独立 gamma/beta → 更细粒度条件化
  3. 调制 decoder 计算, 不修改输入
  4. 零初始化 → 渐进学习, 不影响早期训练

2026-04-20  TFAC V5 Stage 1: Latent Foresight 预训练 (TactileVAE latent 空间)

【动机与核心思路】

2026-04-21  Δφ-weighted L1: 物理变化量加权的 L1 损失

  背景:
    G-TCL 实验完成但效果不佳 (loss 不收敛, 预测比 baseline 差 7.8%)。
    根本原因: 对比学习在投影空间做, 与预测任务脱节。
    需要更直接的方法让模型关注 bounce 等动态时刻。

  核心思想:
    对每个样本 i, 计算 Δφ_i = ||z_target - z_current||₂ (物理变化量),
    然后加权: weight_i = 1 + α * Δφ_i / mean(Δφ)
    动态帧 (bounce) 的 Δφ 更大 → L1 权重更大 → 模型更关注这些帧。

  公式:
    loss_latent = mean(weight_i * |t_hat_i - z_gt_i|)
    其中 weight_i = 1 + α * Δφ_i / (mean(Δφ) + ε)
    α = 2.0 (默认), Δφ = ||z_gt - z_current||₂

  文件改动:
    - TFAC_V5/pretrain_latent_foresight.py: compute_loss 新增 delta_weighted/delta_alpha 参数
    - TFAC_V5/config_pretrain_delta_weighted.json: 独立实验配置

  训练指令:
    python TFAC_V5/pretrain_latent_foresight.py --config TFAC_V5/config_pretrain_delta_weighted.json

2026-04-21  TFAC V6 完整方案设计: 触觉前瞻引导动作筛选

  背景:
    V5的fusion实验显示: gate fusion中memory权重67%, foresight仅15%
    → 被动融合效果有限 (A2比A1仅提升13.3%)
    需要更直接的方式利用触觉预测

  数据分析发现:
    - Success/Bounce的力信号高度重叠 (均值17.5 vs 16.6N)
    - 单帧触觉变化量在碰撞前后差异不明显
    - 核心区别在轨迹层面: bounce比success长63% (293 vs 180步)
    → 单帧信号不足, 需要时序模式判别

  方案核心: Think → Dream → Evaluate → Act
    1. Contact Quality Function (CQF):
       - 触觉latent空间的接触质量评价函数
       - 输入: (z_current, z_future, delta_z) → score ∈ [0,1]
       - 训练: success eps全部标1, bounce前段标0后段标1
       - 利用自然的success/bounce区分, 无需额外标注

    2. Foresight Consistency Loss:
       - 可微分链: Decoder→Foresight(frozen)→CQF(frozen)
       - 梯度从评价函数流向动作参数
       - 训练时内化"好接触"偏好, 推理时零开销

    3. Best-of-K Tactile Selection:
       - 推理时采样K个CVAE候选, CQF打分, 选最优
       - K=1(快速模式), K=4-8(最优模式), 自适应模式

    4. Score-Weighted BC:
       - 高CQF分数的样本权重更大 → 重点学习高效行为

  架构变化 (相对V5):
    - 去掉双decoder设计 (单decoder + CQF替代)
    - 去掉GatedFusion模块
    - 新增CQF (~200K params, 轻量MLP)
    - 新增Consistency Loss (L_consistency = -log(score))

  训练流程:
    Stage 0: TactileVAE ✅ 已完成
    Stage 1: ForesightTransformer ✅ 已完成
    Stage 2: CQF预训练 (NEW, ~2h)
    Stage 3: 联合训练 (TFAC V6)

  风险与Plan B:
    最大风险: CQF区分力不足 (触觉latent重叠)
    验证标准: Stage 2后AUC-ROC > 0.7 → 方案可行
    Plan B: 加时序上下文 / 多模态评分 / 对比学习 / 回退fusion

2026-04-22  MDN Latent Foresight: 多模态预测解决 bounce 模糊性

  背景:
    4 种 Stage 1 变体对比实验结果:
    - Baseline L1: val=0.2072, bounce ep179 L1=0.2607
    - DW (Δφ-weighted L1): val=0.1958, bounce ep179 L1=0.2592
    - G-TCL v2 (对比学习): val=0.2020, bounce ep179 L1=0.2565
    - Delta-Pred (Δz 辅助): 训练中
    所有改进在 2-5% 范围, L1 框架下的改进有天花板。

    G-TCL v2 失败分析:
    - 对比 loss 一直卡在 ln(2)=0.6931 (随机基线)
    - 原因: t+H 和 t+H-1 帧在 latent 空间太相似, 无法区分正负样本
    - 结论: 相邻帧做 hard negative 本质上不可行

    根本原因 (bounce 预测困难):
    - 多模态问题: 同一观测状态 → 两种可能的未来 (平滑插入 vs bounce 接触)
    - L1 回归必须平均两个模式, 产生无效的中间值
    - 这不是 loss 权重能解决的, 需要根本性改变预测头

  核心设计 — MDN (Mixture Density Network):
    输出 K 个高斯模式 {(μ_k, σ_k, π_k)}, K=2
    Loss = -log Σ_k π_k · N(z_gt | μ_k, σ_k) (NLL)
    每个模式独立学习, 不存在模态平均问题

  MDN Head 结构:
    input (B, 144) → shared MLP (144 → 256 → 256)
    → mu_head: Linear(256, K*144) → (B, K, 144)
    → log_sigma_head: Linear(256, K*144) → exp → clamp [0.01, 10] → (B, K, 144)
    → pi_head: Linear(256, K) → softmax → (B, K)

  评估指标:
    - NLL: MDN 原生指标 (越小越好)
    - Best-mode L1: π最大的模式的 μ 与 GT 的 L1 距离 (可与 baseline 直接对比)
    - Oracle-mode L1: 离 GT 最近的模式 (cheating metric, 衡量覆盖能力)
    - Mode usage: 各模式被选中的频率 → 监控模式崩塌

  Loss:
    total = NLL + 0.3 * obs_aux (SmoothL1 marker space)

  实现:
    - 新建文件 (不修改现有代码):
      - TFAC_V5/pretrain_latent_foresight_mdn.py: MDN模型 + 训练循环
      - TFAC_V5/config_pretrain_mdn.json: K=2, hidden=256
      - TFAC_V5/eval_latent_foresight_episode_mdn.py: 多模式 quiver 可视化

  训练结果 (2026-04-22, 500 epochs, K=3):
    - Best epoch: 166 (val NLL=74.43)
    - Best-mode L1 (val): ~0.25
    - Bounce ep179 L1: 0.2953 (比 baseline 0.2607 差)
    - **严重 Mode Collapse**: Mode 0 独占 100%, Mode 1/2 完全死亡
    - Oracle-mode L1 = Best-mode L1, gap=0.0000 → 3个mode输出完全相同
    - 结论: Vanilla MDN 在 144 维高维 latent 空间上 mode collapse 不可避免
    - 需要 entropy regularization / mode dropout 等技巧, 但优先级不高

  目的: 验证 ForesightTransformer 是否真的利用 action 条件信息
  方法: 固定 obs (图像+触觉+qpos), 替换不同的 action, 对比触觉预测差异

  模型: DW (Δφ-weighted L1), ckpt: latent_foresight_pretrain_dw
  数据: 260407/success (90 episodes), 取 ep 0/10/30/50/70, 每个 4 个时间步

  测试条件 (保持 obs 不变, 替换 action):
    1. GT action — 基准
    2. 其他 episode action — 完全不同的轨迹
    3. GT + noise σ=0.5 — 小扰动 (归一化空间)
    4. GT + noise σ=2.0 — 大扰动
    5. Zero action — 关节零位 (物理上不合理的 action)
    6. Reverse action — GT 关于当前 qpos 的镜像

  结果 (20 个测试点平均):

    | Action 类型        | Δ (L2)  | % of pred scale | 说明                  |
    |-------------------|---------|-----------------|-----------------------|
    | GT (self)         | 0.0000  | 0.0%            | 基准                  |
    | noise σ=0.5       | 0.2272  | 11.9%           | 小扰动 → 小变化       |
    | other episode     | 0.2937  | 15.4%           | 不同轨迹 → 中等变化   |
    | reverse action    | 0.3613  | 19.0%           | 反向 → 较大变化       |
    | noise σ=2.0       | 0.8958  | 47.1%           | 大扰动 → 大变化       |
    | zero action       | 1.8668  | 98.2%           | 物理不合理 → 近乎完全不同 |

  Avg prediction scale: 1.90
  Avg GT scale: 11.16
  Avg pred error (vs GT): 10.81

  关键结论:
    1. **Foresight 对 action 敏感** — SENSITIVE verdict
       不同 action 产生不同的触觉预测, 且变化量与 action 偏差程度单调递增
    2. **敏感性有层次**: 小扰动(12%) < 其他ep(15%) < 反向(19%) < 大扰动(47%) < 零action(98%)
       这种层次化响应说明模型学到了合理的 action→tactile 映射
    3. **绝对预测精度差**: pred scale=1.90 vs GT scale=11.16 (仅17%)
       原因: DW 模型训练数据是 xiaomi_act/data (337 episodes, 260309_0310),
       测试用的 260407 是不同任务的数据, 存在 domain gap
    4. **Reranking 可行性**: 虽然绝对精度差, 但相对排序是正确的
       不同 action 给出不同预测 → 用 foresight 评分来 rerank 候选 action 是可行的
       (在同分布数据上精度会更好, 评分区分度也会更强)

  下一步:
    - 在同分布数据 (260309_0310) 上用训练好的 foresight 模型重新测试敏感性
    - 实现 CQF (Contact Quality Function) 5 维评分体系
    - 端到端验证: DP 生成 K=16 候选 → foresight 评分 → rerank → 与 oracle 对比

  文件: scripts/test_foresight_sensitivity.py

[2026-04-23] Foresight Action 敏感性可视化 (正确版本 — LatentForesightPretrainModel)
===============================================================

  背景:
    上面的 test_foresight_sensitivity.py 用了错误的模型类 (ForesightPretrainModel),
    DW checkpoint 实际是 LatentForesightPretrainModel, strict=False 静默忽略了不匹配的权重,
    导致预测精度很差 (pred scale=1.90 vs GT=11.16)。

    本次用正确的 LatentForesightPretrainModel 重写可视化脚本,
    参考 eval_latent_foresight_episode.py 的模型加载和数据处理逻辑。

  模型: /home/chenshuai/data/xiaomi_act/latent_foresight_pretrain_dw/
    - LatentForesightPretrainModel (TactileVAE latent space)
    - 训练数据: 260407 (182 episodes = 90 success + 90 bounce + 2 test)
    - chunk_size=10, foresight_horizon=10, tactile_vae_latent_dim=16, tactile_vae_window=8
    - delta_weighted=true, delta_alpha=2.0

  实验设计:
    给定同一观测 (视觉 + 触觉 + qpos), 分别喂入5种不同action:
    1. GT action — 真实动作
    2. Noise σ=0.5 — 归一化空间小扰动 (半个标准差)
    3. Other Episode — 替换为 success/episode_10 同时刻的 action
    4. Noise σ=2.0 — 归一化空间大扰动 (2个标准差)
    5. Zero Action — 全零动作 (归一化后)

    对每种 action, foresight 预测未来触觉 latent, decode 回 marker 空间 (9x9x2),
    与 GT action 的预测做对比, 计算 L1 差异。

  测试用例:
    A. Success episodes: ep0_t50, ep0_t100, ep30_t50, ep30_t100
    B. Bounce episodes (关键!):
       - ep100: bounce peak at t=148 → 测 t=130(pre), t=148(at), t=165(post)
       - ep130: bounce peak at t=139 → 测 t=120(pre), t=139(at), t=160(post)

  结果 — 预测精度 (GT action vs GT future):
    所有 case: L1=0.14~0.31, Cosine=0.95~0.99 → 模型预测精度很好

  结果 — Success 场景 Action 敏感性:
    | 扰动类型       | Δ vs GT-pred (range)  |
    |---------------|-----------------------|
    | Noise σ=0.5   | 0.07 ~ 0.66           |
    | Other Episode | 0.07 ~ 0.29  (小!)     |
    | Noise σ=2.0   | 0.78 ~ 3.63           |
    | Zero Action   | 4.0 ~ 4.4             |

    Success 场景下, Other Episode 差异很小 → 因为都是类似的抓取任务,
    同时刻的 action 本身就差不多。

  结果 — Bounce 场景 Action 敏感性 (核心发现!!):
    | 扰动类型       | pre-bounce | at-bounce    | post-bounce   |
    |---------------|-----------|--------------|---------------|
    | Noise σ=0.5   | 0.66~1.04 | 0.10~0.25   | 0.09~0.14     |
    | Other Episode | 0.57~0.90 | **3.42~6.49**| **3.76~4.71** |
    | Noise σ=2.0   | 0.53~0.75 | **2.30~5.51**| 0.15~2.71     |
    | Zero Action   | 3.26~3.27 | 3.76~6.24   | 3.76~3.99     |

  关键结论:
    1. **Bounce 时刻对 Other Episode action 极其敏感**:
       Success 场景 Other Episode Δ = 0.07~0.29
       Bounce at/post Δ = 3.42~6.49  (10-50 倍差异!)
       → 在接触关键时刻, 不同 action 导致截然不同的触觉后果

    2. **Foresight 模型学到了 action-tactile 因果关系**:
       不是简单忽略 action 输出固定预测, 而是真正理解了
       "这个动作在当前状态下会产生什么样的触觉变化"

    3. **敏感性与任务阶段相关**:
       - Success 平稳阶段: action 间差异小 (任务相似)
       - Bounce 关键时刻: action 间差异极大 (此时 action 选择决定成败)
       → 这正是 reranking 最有价值的时刻!

    4. **从 diff heatmap 空间分布看**:
       Bounce 时刻整个 9x9 传感器区域都受影响 (mean=6.43, max=8.26)
       不是局部现象, 而是全局性的触觉变化

    5. **验证了 "用触觉预测 rerank action" 的可行性**:
       Foresight 能在关键时刻区分好/坏 action 的触觉后果
       → 可以作为 action candidate 的评分函数

  可视化输出: /home/chenshuai/Project/output/foresight_sensitivity_vis/
    - sensitivity_*.png: quiver 对比图 (GT vs 各种 action 的预测箭头)
    - diff_*.png: 热力图 + summary 柱状图

  文件: scripts/vis_foresight_sensitivity.py (使用 LatentForesightPretrainModel)

[2026-04-23] 三版 Diffusion Policy 实现对比与 Gap 分析
===============================================================

  对比了三个 DP 实现版本:
  A. diffusion/             — 项目原版 DP (来自原始 TactileACT 论文代码)
  B. scripts/train_dp_joint.py — 改进版 DP (适配小米数据 7D joint_abs)
  C. diffusion_policy_official/ — 官方 DP (Chi et al. RSS 2023, 已 clone 到项目下)

  官方代码: https://github.com/real-stanford/diffusion_policy
  已加入 .gitignore, 不纳入 git 管理

  核心差异对比:
  ┌──────────────────┬──────────────┬──────────────────┬──────────────────┐
  │ 项目             │ 原版 diffusion│ train_dp_joint   │ 官方 DP          │
  ├──────────────────┼──────────────┼──────────────────┼──────────────────┤
  │ Action 空间      │ 4D EEF       │ 7D joint_abs     │ 任务相关         │
  │ obs_horizon      │ 1            │ 2                │ 2                │
  │ EMA              │ 无(注释掉)   │ 有(power=0.75)   │ 有(power=2/3)    │
  │ 数据采样         │ 每ep采1帧    │ 每ep采1帧        │ 滑动窗口穷举     │
  │ UNet kernel      │ 5            │ 5                │ 3                │
  │ embed_dim        │ 256          │ 128              │ 256              │
  │ cond_predict_scale│ 无          │ 无               │ 有(FiLM scale+bias)│
  │ RandomCrop       │ 无           │ 无               │ 有(76x76)        │
  │ Batch size       │ 8            │ 16               │ 256              │
  │ 触觉             │ GelSight img │ GelSight img     │ 无               │
  │ 视觉编码器       │ ResNet18独立 │ CLIP ResNet18共享│ ResNet18+BN→GN   │
  └──────────────────┴──────────────┴──────────────────┴──────────────────┘

  TFAC_V5 的数据采样:
    __len__ = len(episode_ids) * 30, 即每epoch每episode采30帧
    DW foresight 为例: 145 train eps × 30 = 4350 样本/epoch, bs=128, 34 batch/epoch
    官方 DP 滑动窗口: 145 eps × ~200帧 = 29000 样本/epoch (6.7倍)
    DP baseline (×1): 145 eps × 1 = 145 样本/epoch (差200倍!)

  四个关键 Gap (初始分析):
    1. 数据采样: 我们每ep随机采1帧, 官方穷举所有帧 → 差200倍数据利用率
    2. RandomCrop: 官方对图像做random crop到76x76, 我们无数据增强
    3. cond_predict_scale: [误判!] 检查代码发现 diffusion/network.py 的
       ConditionalResidualBlock1D 已经是 scale+bias (cond_channels=out_channels*2,
       out=scale*out+bias), 和官方一致, 不需要改
    4. Batch size: 官方256 vs 我们16

  已完成修改:
    - 数据采样: 修改 scripts/train_dp_joint.py 的 DPJointDataset,
      从 "每ep随机采1帧" 改为 "滑动窗口穷举所有帧"
      __init__ 预扫描所有 episode 长度, 建立 (ep_id, start_ts) 索引表
      __len__ 返回总帧数, __getitem__ 按索引确定 episode 和起始帧
      例: 145 eps × ~180帧 ≈ 26000 样本/epoch (原来只有 145)
