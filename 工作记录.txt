2026-04-16  TFAC V4 (LDG) 完整实现
---------------------------------------------------------------
任务: 基于 V3 问题分析和论文调研，设计并实现 TFAC V4 (TFAC-LDG)
目标: CoRL 2026 论文, 故事线 Think → Dream → Verify → Act

【V3 五大问题】
1. 单 token 触觉瓶颈: 81个标志点压缩到1个token，空间结构丢失
2. 只用最后帧: 10帧预测只取 frame[9]，中间帧信息浪费
3. A1 完全 detach: foresight 质量无法反传到 draft action
4. 弱对比学习: 63个负样本, GT contrastive 禁用, lambda=0.1
5. SpatialTactileDecoder: 从单一全局向量重建 9×9 损失大

【V4 五大创新 (C1-C5)】
C1: SpatialMarkerEncoder — 9 spatial patch tokens
   - (B,9,9,2) → per-point MLP(4→64→128→D) → +pos_embed → 2-layer SelfAttn → 3×3 patch_pool → (9,B,D)
   - 保留空间结构，支持per-patch对比学习

C2: Latent Prediction + Dynamic-Aware Weighted Loss
   - 在潜在空间监督: encode GT marker → spatial tokens → smooth_l1 vs predicted tokens
   - 动态权重: weight = sqrt(change/mean_change)，变化大的帧权重更大

C3: Tactile Consistency Loss (核心创新)
   - 动作→触觉因果验证: TactileDynamicsModel 预测 z_next
   - Margin ranking: sim(z_pred, z_gt_next) > sim(z_pred, z_random) by margin=0.2
   - 验证 foresight 预测的触觉轨迹与实际动力学一致

C4: Temporal Differential Residual Action
   - A2 = A1 + sigmoid(alpha) * deltaA
   - alpha 可学习，初始化 0.1 (sigmoid ≈ 0.525)
   - TactileTrajectoryEncoder: 时序差分编码 [frame0, diff1, diff2, ...] → summary

C5: Multi-level Contrastive Learning
   - Spatial: per-patch InfoNCE, (B,9,D) vs (B,D) → B*9 负样本
   - Temporal: margin ranking, 相邻帧 > 远距帧
   - GT alignment: 预测视觉 vs GT视觉 标准 InfoNCE

【新增模块】
- TFAC_V4/marker_encoder.py: SpatialMarkerEncoder
- TFAC_V4/foresight_transformer.py: ForesightTransformerV4, PatchLevelDecoder, ForesightContrastiveV4
- TFAC_V4/tfac_model.py: TactileDynamicsModel, TactileTrajectoryEncoder, ContactAwareFusion, TFACModelV4
- TFAC_V4/tfac_policy.py: TFACPolicyV4 (全部 loss 计算)

2026-04-16  TFAC V4 训练调优 (OOM 修复 + AMP)
---------------------------------------------------------------
任务: V4 首次正式训练 (0414 数据集, 162 episodes, 2000 epochs)

【OOM 问题与修复历程】
1. batch_size=64: epoch 0 validation OOM (23.9GB/24.6GB)
2. batch_size=32: epoch 4 training OOM (sampling loss rollout 累积显存)
3. batch_size=16 + grad_accum=2: epoch 14 OOM (19.5GB allocated + 2GB fragmentation)
4. batch_size=8 + grad_accum=4: epoch 18 OOM (19GB + 2.5GB fragmentation)
5. + sampling loss detach (中间步骤不保留梯度图): epoch 19 OOM (仍然太接近上限)
6. + AMP 混合精度: epoch 20 OOM (19GB peak 未显著下降)
7. batch_size=4 + grad_accum=8 + AMP + CPU state_dict: epoch 1 matplotlib tkinter crash
8. + matplotlib.use('Agg'): 当前运行中，预期稳定

【根因分析】
- V4 模型 122M 参数, 包含: 共享encoder + 双decoder(7+7层) + foresight(3层) + dynamics + trajectory encoder
- Sampling loss 做 3 步自回归展开, 每步一个 foresight forward pass
- 训练 ~20 epochs 后 CUDA 内存碎片化导致 OOM (reserved but unallocated ~2.5GB)
- Peak memory 稳定在 ~19GB, 24GB GPU 仅余 ~5GB, 碎片化后不足

【最终训练配置】
- batch_size=4, grad_accum_steps=8 (有效 batch=32)
- AMP 混合精度 (GradScaler + autocast)
- Sampling loss 中间步骤 detach (仅最后一步保留梯度)
- Best checkpoint 实时保存 (不等训练结束)
- State_dict 存 CPU (节省 ~490MB GPU)
- torch.cuda.empty_cache() 每 epoch
- matplotlib Agg 后端 (避免 tkinter crash)
- ~107s/epoch, 预计总训练时间 ~60 小时

【早期收敛趋势 (前 15 epochs, 非 AMP+bs4 run)】
- Epoch 0:  val l1_final=1.482, train_loss=5.61
- Epoch 5:  val l1_final=0.262, train_loss=1.30
- Epoch 10: val l1_final=0.205, train_loss=0.74
- Epoch 15: val l1_final=0.203, train_loss=0.50
- 所有 17 个 loss 正常收敛
- Gate 演化: a1_gate 持续上升 (0.34→0.42), traj_gate 缓慢上升 (0.27→0.28)

2026-04-16  V4 Ablation 实验 (V1 recipe + SpatialMarkerEncoder)
---------------------------------------------------------------
任务: V4 CLIP backbone 训练效果差 (plateau 0.171)，需要深度分析根因并迭代

【V4 vs V1 根因分析】
问题: V4 best l1_final=0.171 (CLIP) / 0.155 (ImageNet) vs V1=0.072

核心差异 (V4 → V1):
1. kl_weight: 1 → 10   → V4 KL=0.00004 完全崩塌, V1 KL 正常
2. a2_init: "residual" → "a1_refine"  → V4 A2≈A1 (cosine=0.998), V1 A2改进6.5%
3. 12 个 loss 竞争 → 6 个简洁 loss   → V4 loss 之间互相干扰
4. batch_size: 有效32 → 64           → V4 被 OOM 限制
5. predict_horizon: 10 → 1            → V4 多帧预测远帧退化 3.3x
6. fusion: contact_gate → gate        → V4 过度复杂
7. dec_layers_draft: 7 → 3            → V4 draft decoder 过重
8. lambda_foresight_vis: 0.3 → 0      → V1 禁用视觉预测 loss

【隐藏 Bug 发现】
predict_horizon=1 + foresight_horizon=10 → 数据集返回 (B,10,9,9,2)
但模型期望 (B,9,9,2)，dim 不匹配导致 foresight loss 全部静默为 0！
修复: _compute_gt_future_features 中提取最后一帧

【V4 Ablation 策略 (回归 V1 + 保留 SpatialMarkerEncoder)】
- 假说: V4 的 SpatialMarkerEncoder (9 spatial tokens) 是有价值的创新
  其他创新 (C2-C5) 同时引入导致训练不稳定
- 方法: 用 V1 验证过的 recipe + 只加 SpatialMarkerEncoder
  如果 V4.1 > V1 → C1 是有效创新，可以逐步加回 C2-C5
  如果 V4.1 < V1 → C1 可能有害，需要重新设计

config_v4_ablation.json 关键设置:
- kl_weight=10, a2_init="a1_refine", fusion_mode="gate"
- predict_horizon=1, sampling_steps=0, history_len=1
- lambda: draft=0.5, obs=0.7, contrastive_gt=0.1, 其余=0
- dec_layers_draft=3, batch_size=16, grad_accum=4 (有效 bs=64)
- 模型参数: 103.30M (vs V4 122.26M)
- curriculum_ratio=0.75 (V1 值)
